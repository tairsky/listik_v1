# Листик: памятка для Claude

Листик это ИИ-репетитор-тренажёр для детей 8–10 лет (сейчас математика, 3 класс, Казахстан). Он НЕ помогает с домашними заданиями и не проверяет их: упражнения свои. Проверка домашки это отложенный модуль на будущее.

## Сначала прочитай
- `prd.md`: что за продукт, для кого, что есть и чего нет, риски.
- `architecture.md`: как устроен код, файлы, данные, настройки.
Если что-то в них расходится с кодом, верь коду и скажи мне одной строкой «Вне задачи заметил: файл устарел». Сам обновлять и предлагать обновить их не нужно, пока я не попрошу.

## Правила
1. Отвечай по-русски, коротко и просто. Что не проверено, помечай словом «не проверено». Не выдумывай.
2. Секреты: файл `.env` не читай и не выводи. Папку `Payment/` не открывай и не добавляй в git (там реквизиты).
3. Перед правкой файла сделай копию рядом с именем `<файл>.before_<слово>` (так заведено в проекте).
4. Ничего не удаляй. Лишнее переноси в `_to_delete/`.
5. `node build-audio.js` не запускай без моего разрешения: он тратит деньги OpenAI.
6. Боевой сайт (listik.kz) живёт на VPS у Hoster.kz (домен куплен в PS.KZ, DNS там же). Выкладка только через `vylozhit_ps.command` (копирует файлы по SSH и перезапускает службу) и только когда я попрошу. `git push` сам не делай. Старые `vylozhit*.command` работают с GitHub и Render (тестовый сайт listik-test), для боевого не использовать.
7. Тексты на сайте говорят «тренажёр» и «занятия», не «домашка» и не «поможем с домашним заданием».
8. Правильность ответа ребёнка проверяет код, не ИИ. Ответ ребёнку никогда не называем.
9. Казахская версия: после правки русского текста добавь перевод в `kk_tools/kk_dict_extra.json`. `kk_tools/build_kk.py` без пополненного словаря не запускай. Казахские тексты пишу не я, их должен проверить носитель.
10. Упражнения, подписи ошибок и методику учитель ещё не проверял, это гипотезы автора. Так и называй.
11. Если задача из нескольких шагов (проверки, настройка, выкладка), сначала назови общее число шагов. Показывай только один шаг за раз. Следующий шаг показывай после того, как я подтвержу, что предыдущий выполнен.

12. Одна задача за раз, строго в её рамках.
- Делай только то, о чём я попросил. Не предлагай дополнений, улучшений, «заодно» и «ещё можно».
- Если видишь рядом другую проблему, не чини и не обсуждай её. Максимум одна строка в конце: «Вне задачи заметил: …». Без предложений, пока не спрошу.
- Закончив, пиши: «Задача решена и закрыта», затем 1–2 предложения, что изменено, и как проверено (или «не проверено»).
- В конце не предлагай следующих шагов и не перечисляй другие направления. Список давай, только если спрошу «что ещё есть».
- Если для задачи нужен мой ответ, задай один вопрос до начала работы, а не в процессе.

## Где что
- Сервер: `server.js`. Оплата: `pay.js` (настоящий банк не подключён, работает заглушка). Упражнения: `data/private/tasks.json`, навыки и ошибки: `data/private/skills.json`.
- Данные кабинетов: `storage/` (в git не попадает).
- Хостинг (с 10.11.2026): VPS Hoster.kz (домен и DNS в PS.KZ), Ubuntu 24.04, 2 ГБ / 2 ядра / 40 ГБ. Код в `/opt/listik`, данные в `/data` (`STORE_DIR`), служба `systemctl ... listik`, nginx и сертификат Let's Encrypt (certbot), переменные в `/etc/listik.env` (не читать и не выводить). Ежедневная копия `/data` в `/var/backups/listik` (хранится 14 дней), копия на Mac вручную в `~/listik_backups`. Вход на сервер только по SSH-ключу с компьютера автора. Render оставлен только для теста (`listik-test`, ветка `test`).
- Документы проекта (методика, планы, журналы) лежат в проекте «Listik» на claude.ai.
